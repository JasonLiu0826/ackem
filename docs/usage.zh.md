# 使用指南

[English](usage.md) · [文档导航](README.md)

## 安装与启动

安装和源码快速启动见 [README](../README.md#-下载与安装)。选择与平台匹配的发行包；Windows 便携版完整解压后运行。macOS 的签名、依赖和验证范围以对应发行说明为准。

应用首次启动需要配置模型，部分渠道还需等待本地语义资源准备。遇到启动问题先核对实际模型、内核进程和数据目录，见[模块参考](modules.zh.md#ackemcode)。

## 设置与模型

| 设置 | 用途 |
|---|---|
| 模型与 API | 主对话、语义判断等使用的模型地址、密钥与模型名 |
| 工作执行 | AckemCode 模型、工作权限及远程派工 |
| 伴侣与人格 | 人格预设、表达及陪伴相关选项 |
| 手机／移动端 | QQ、微信连接与机主确认 |
| 数据与系统相关设置 | 数据位置、语义资源及运行状态，以实际界面为准 |

可以使用云服务或本地兼容接口；按服务要求填写 endpoint、key 和 model。Ackem 不捆绑对话 LLM。本地模型也需要验证多轮工具调用能力；普通对话成功不代表工作执行已通过验证。

前台窗口、剪贴板、截图、麦克风等能力是否可用，取决于对应模块、平台、开关与授权。不要将未启用的能力理解为后台持续采集。主应用与内核模型配置同步的差异只在[模块参考](modules.zh.md#ackemcode)维护。

## 请求如何处理

正常描述你希望完成的事情，Ackem 根据本轮意图、最近对话和可用能力选择 chat／plugin／work。以下例子说明处理边界，不是关键词匹配规则：

| 请求示例 | 处理方式 | 预期结果 |
|---|---|---|
| “解释一下这个概念”“给我一份目录整理方案” | chat | 在对话中给出解释或方案 |
| “用已启用的某个插件处理这段内容” | plugin | 核验并调用对应扩展，结果以真实回执为准 |
| “检查这个项目实际使用了哪些模块” | work | AckemCode 读取真实项目并返回检查结果，即使不修改文件 |
| “把这份内容保存成文件”“整理这个真实目录” | work | 执行文件操作并交付产物或清单 |
| “做一个以后能反复调用的插件” | work | 创建扩展；安装、启用与可调用状态仍需核验 |

“帮我写一段正文”与“生成并保存一个文档文件”要求的结果不同；“搜索”等词也不能单独决定通道，chat 可使用普通聊天工具。请求补充了真实资源操作要求时，会重新结合上下文判断，不要求你从头换一种说法。

插件缺失、判断失败或尚未执行时，不应显示成已经调用成功。模糊指代可能需要澄清；选择了 work 也不等于已派工、已执行或已验收。实现细节和渠道差异统一见[架构说明](architecture.zh.md#三级路由)。

## 工作执行与权限

| 入口 | 如何使用 |
|---|---|
| 聊天托管任务 | 在聊天中明确委托真实操作，Ackem 跟进目标、执行与交付 |
| 工作页独立任务 | 直接输入目标和目录，使用独立会话与输入队列 |
| 渠道代码派工 | 确认机主、开启远程派工后，从 QQ／微信提出代码类请求 |

工作默认从活跃数据根的 `workspace/` 开始，也可选择其他目录。**工作目录是起点，不是全局文件白名单。** 完全放开模式可能操作目录以外的资源；审批、任务的只读／排除约束与实际权限共同控制执行。

需要停止时使用停止或接管入口，并核对停止回执。关闭页面、隐藏窗口或断开事件流不表示执行已停止。补充目标、排队、返工和执行／验收／交付的区别见[架构说明](architecture.zh.md#任务生命周期)。

## 渠道

### QQ

1. 按协议端自身说明部署 OneBot v11 服务，并登录 QQ 账号。登录态由协议端维护；Ackem 不接管 QQ 密码。
2. 在设置的 QQ 页面配置 WebUI／连接地址及令牌；使用当前支持的扫码与连接测试流程。
3. 保存并启用连接，发送私聊验证收发，再在桌面确认渠道机主。
4. 需要从手机操作本机时，额外开启 **设置 → 工作执行 → 远程派工**，并核对远程权限。

使用协议端实际开放的 HTTP／WebSocket 地址和相应 token，不混用 WebUI 令牌与 OneBot token。排错时分别检查登录态、连接测试、机主状态、模型和语义资源。

QQ 支持的语音、表情与空间互动按各自配置启用。用户表情目录为 `<dataRoot>/qq-memes/`，内置素材及署名见 [QQ 素材](../assets/qq-memes/CREDITS.md)。空间发布、评论、点赞等可能产生真实平台操作，先检查账号、试运行、时段与频率设置。

### 微信与跨端会话

在移动端设置中完成当前支持的微信接入和机主确认，再验证消息收发。渠道回复发送给本轮提问端；历史和人格的共享不代表执行入口相同。

QQ／微信当前使用代码请求桥接，支持 `/code` 等显式前缀及工程类规则；**含用户图片的轮次跳过代码派工判断**。尚未完整接入桌面通用语义路由和托管监督链。

远程派工默认关闭；开启后默认权限为 `bypassPermissions`，可收紧设置。`ACKEMCODE_PERMISSION_MODE` 环境变量优先于远程设置；旧远程授权可迁移到 `workRemoteChannelsEnabled`。模式、模型和工作目录变更后应核对实际会话，不能承诺撤销已经发生的操作。

## 数据与隐私

| 位置 | 主要内容 |
|---|---|
| 活跃 Ackem 数据根 | `ackem.db`、记忆、历史、日记、用户扩展、模型缓存和默认工作目录等 |
| Electron userData | 应用设置、凭据相关数据及渠道会话映射 |
| AckemCode 实际数据目录 | 内核会话、配置、工具与任务状态 |
| 用户选择的工作目录 | 实际修改的文件与生成的产物，可在数据根之外 |
| 外部服务与渠道 | 模型、搜索、工具及平台按各自行为接收或保存的数据 |

便携开发通常使用 `<cwd>/data/`，便携发行版使用程序旁 `data/`；用户目录模式按平台解析。以设置和实际运行路径为准。[存储参考](modules.zh.md#存储)说明具体目录与数据库。

本地优先不表示无数据出站。云模型会收到被选入上下文的消息、记忆、附件或工具结果；搜索、MCP、语音及 QQ／微信可向相应服务发送内容。不要假定数据只流向一个模型地址，或所有临时产物都会即时删除。

应用设置中的系统加密与内核 `settings.standalone.json` 不是同一种机制；模型同步可能把密钥写入内核 JSON。备份、排障及分享文件时需同时检查两边。

备份或迁移时，先停止任务、退出应用和相关服务，再复制活跃数据根、需要的 userData、内核数据及外部产物。在副本上验证升级和任务恢复。完全清除时分别处理这些位置；卸载应用或删除单个 `data/` 目录不会清除所有外部文件或平台消息。

索引缓存可按实现重建；事实、历史、契约、回执和工作产物不能当作缓存删除。纠正、遗忘与检索的关系见[记忆引擎](companion-engines.zh.md#记忆引擎)。

## 内容设置

成人模式默认关闭，相关设置只影响陪伴内容和表达，不授予文件、终端或持续执行权限。成人内容仅面向成年人；用户可关闭相关模式并拒绝亲密推进。应用策略与所选模型的内容政策共同影响输出，不承诺能完美识别全部违规内容。

亲密内容的检索与注入受记忆隐私级别和当前模式约束，不能将“存储过”理解为“每次都会发给模型”。实际过滤入口见 [retriever](../src/main/memory/retriever.ts) 与 [interpreter](../src/main/engine/interpreter.ts)。

安全问题按[安全策略](../SECURITY.zh.md)报告；开发者的排障和发行检查见[开发指南](development.zh.md)。
