# 源码验证与运行验收

[English](testing.md)

## 检查范围

| 命令 | 范围 |
|---|---|
| `npm run typecheck` | 渲染层与共享类型 |
| `npx tsc --noEmit -p tsconfig.node.json` | 主进程与 preload |
| `npm --prefix parts/ackemcode run typecheck` | 内核服务、CLI 与 Web UI |
| `npm --prefix parts/ackemcode run build` | 独立内核编译 |
| `npm run build` | Electron 主应用编译 |

先分别 `npm ci` 与 `npm --prefix parts/ackemcode ci`。当前 CI 使用 Windows / Node.js 22。根构建脚本使用 Windows shell 语法。

公开仓库不分发完整本地测试套件；已有少量跟踪用例不代表全套。不要列不存在的 `npm test` 或依赖私有测试辅助文件的公开验收命令。

## 有意义的运行检查

- chat：普通对话、记忆检索、流式正文、图片/文件与历史。
- plugin：已启用能力真实调用，未安装/禁用时不伪造成功。
- work：创建任务、目标补充、队列、权限交互、工具结果、验收/返工与最终正文。
- 停止与恢复：请求停止后核对静止回执；重启与旧事件不得覆盖新目标。
- 独立工作：私有队列、模式、CLI 与页面隐藏时的行为。
- QQ / 微信：机主确认、远程开关、权限变更、提问端回复和统一历史。
- 打包：干净目录启动、内核启动入口、模型配置、数据留存与资源路径。

每项记录输入、实际输出、检查环境与未覆盖范围。真实模型、渠道和外部工具依赖服务与凭据。

## 原生模块与异步测试

`better-sqlite3`、`node-pty` 等必须匹配加载它们的 Node / Electron ABI。原生加载失败是环境失败，不是数据库逻辑验证通过。更换 ABI 后核对应用是否仍可启动。

测试进程退出码为 0 但缺少最终统计，也不能视为所有用例完成。区分通过、跳过、提前返回、超时和收集未完成。定向测试不能外推成完整回归。

文档改动应检查链接、源码路径、命令与语义一致性；通常无需重新运行业务测试。
