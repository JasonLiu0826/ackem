# 敏感能力与执行边界

[English](sensitive-capabilities.md) · [隐私与数据](privacy-and-data.zh.md)

## 能力与控制

| 能力 | 涉及内容 | 控制方式 |
|---|---|---|
| 模型与语义路由 | 对话、记忆片段、人格、附件和任务上下文 | 模型设置与上下文选择 |
| AckemCode work | 文件读写、命令、联网、文档和外部工具 | 当前任务/会话权限、只读与排除约束、审批和停止 |
| QQ / 微信 | 平台消息、图片、音频与本机回复 | 渠道连接、桌面机主确认 |
| 远程代码派工 | 从渠道驱动本机内核 | 工作执行设置默认关闭，开启后按远程权限 |
| QQ 空间 | 说说、图片、评论、点赞与浏览互动 | 空间功能设置、试运行、时段/频率与平台能力 |
| 语音 | 麦克风、待合成文本、音频产物 | 语音开关与本机/外部服务选择 |
| 感知与插件 | 前台、剪贴板、截图等可用能力 | 对应模块状态和扩展权限 |
| 导入和附件 | 用户选择的文件、图片、目录或视频 | 用户输入及实际解析、模型与工具使用 |

能力入口存在，不表示每个平台、每台机器都已具备相同实现。按 registry、manifest、运行时状态和实际工具回执判断，不把 planned/stub 功能描述成可运行。

## 三级路由的权限区别

chat 使用对话和受约束的聊天工具；plugin 执行已启用扩展并遵守该扩展的权限；work 进入 AckemCode，按任务和内核的策略操作真实资源。

扩展 staging 或记忆写入白名单不构成 AckemCode 的全局限制。工作目录也不是全机访问白名单。完全放开模式允许更广的本机操作，限定调查仍有其强制只读范围。

QQ / 微信远程派工需双重条件：已确认机主，且 `workRemoteChannelsEnabled=true`。其默认执行权限是 `bypassPermissions`，可在设置中改为更严格模式，环境变量优先。桌面托管与独立工作权限分别按入口管理。

## 停止、留存与凭据

停止请求与已经停止分开记录；断流或关闭工作页不等于撤销执行。请核对任务回执、进程静止和结果状态。

聊天、任务、回执和工具内容可能保存在应用或内核目录。文件产物可能位于用户选定的外部目录。语音与第三方工具的缓存策略各自不同，不宜笼统承诺“处理即弃”。

应用设置中的系统加密与内核明文 JSON 配置不是同一存储机制。备份、导出和发行包检查需覆盖两边。

## 已删除的旧能力

旧电脑助手的模式、设置页、IPC、`use_computer`、平台执行器、调查、本机地图和旧任务计划已移除。配置兼容迁移不会恢复这些入口；现有任务执行统一使用 work / AckemCode。
