# 隐私与数据

[English](privacy-and-data.md) · [数据目录](memory-format.zh.md)

## 本地优先的含义

Ackem 把应用状态、历史与记忆保存在本机，用户选择模型、渠道和工具。使用云模型时，所选上下文会发往模型服务；搜索、网页、MCP、QQ / 微信以及执行命令也可能产生网络请求。**本地优先不表示所有内容永远不离开电脑。**

## 存储边界

| 数据 | 位置与处理 |
|---|---|
| 聊天、记忆、人格状态、事件与托管任务 | 活跃 Ackem 数据根：SQLite 与相关文件 |
| 日记、导入、用户扩展与派生检索 | 数据根下 `diary/`、`imports/`、`openforu/`、`_derived/` 等 |
| 应用设置与凭据 | Electron userData 的 `ackem-app-settings.json` |
| 内核配置、会话与运行数据 | AckemCode 实际数据目录 |
| 工作输入与产物 | 默认 `<dataRoot>/workspace/` 或用户选择的其他目录 |
| 渠道消息与会话映射 | Ackem 数据库、历史，以及 userData 的渠道内核映射文件 |

数据根可为便携 `data/` 或平台用户目录。桌面启动的内核默认使用 `<codeRoot>/data/`，渠道启动默认 `~/.ackemcode/`，可由 `ACKEMCODE_DATA_DIR` 覆盖。复用已有服务时，以服务进程的实际目录为准。

## 凭据

应用设置对支持的密钥使用 Electron safeStorage，并保留实现中的兼容处理；不要据此认为所有本机副本都已加密。内核同步会写入包含可用 API Key 的 `settings.standalone.json`，格式是 JSON。文件权限不等于加密，尤其在不同操作系统上。

请求模型服务需要使用凭据认证。不要把“凭据不随发行包分发”写成“密钥从不发往服务”。日志、导出、手工修改的配置和第三方插件也应按实际内容检查。

## 哪些内容可能出站

| 功能 | 可能发送的数据 |
|---|---|
| chat 与语义路由 | 当前请求、近期历史、选中记忆、人格或能力上下文 |
| work / AckemCode | 任务目标、会话、读取的文件/附件内容、工具结果和用于推理的上下文 |
| 搜索、网页与 MCP | 查询词、URL、工具参数或服务要求的数据 |
| QQ / 微信与空间 | 发往相应平台的文本、图片、音频和互动内容 |
| 语音 | 取决于选用的本机或外部语音服务 |
| 更新与资源下载 | 版本/资源请求及网络连接信息 |

具体范围取决于用户配置、模型上下文选择和工具操作。记忆检索会选择片段，但不能据此保证某份文件绝不进入模型上下文。

## 执行权限

work 可读写文件、运行命令和使用外部工具。当前工作目录是起点，不能当成全局沙箱。权限模式、任务只读/排除约束和实际工具审批决定操作范围。

QQ / 微信代码派工默认关闭，需要确认机主并开启远程派工。开启后的默认远程模式为 `bypassPermissions`，可在 **设置 → 工作执行** 收紧；环境变量还可覆盖。独立工作与桌面托管任务按各自入口管理权限。

旧助手配置迁移只保留远程授权。删除旧代码不会清理旧日志、历史或用户磁盘上已经生成的文件。

## 备份、迁移与删除

1. 停止任务并退出应用及相关内核服务。
2. 备份活跃数据根、Electron userData、内核实际数据和需要保留的工作产物。
3. 迁移后核对模型配置、服务数据目录及待恢复任务，避免新旧进程同时写同一数据。
4. 完全清除时分别处理以上位置。删除应用文件或仅删除 Ackem `data/`，不等于已经删除内核数据、外部工作文件或平台上的消息。
5. 分享发行包或排障资料前检查私人数据、API Key、令牌、日志和会话内容。

应用没有用于默认集中收集聊天内容的 Ackem 遥测上传链路；配置的模型、渠道和工具仍按各自行为联网。这不构成对外部服务留存行为的保证。
