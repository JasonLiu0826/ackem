# 检索索引、规模与重建

[English](indexing-and-scale.md)

Ackem 使用事实检索、全文/关键词、向量与关联等路径，实际组合取决于运行状态与查询。Embedding 服务是检索基础设施，不是执行授权或路由的唯一依据。

## 原始数据与派生数据

`_derived/` 及部分向量缓存用于加速检索；SQLite 中的事实、历史、事件、契约和任务回执包含权威数据。FTS 与向量数据也可能在数据库中，不能把所有索引都理解为 `_derived/` 文件。

通过应用提供的重建入口操作，避免运行中手工删表。重建索引不等于重新创建事实、清空任务或完成 schema 迁移。

## 规模

性能取决于事实数、文档尺寸、向量模型、硬件、索引状态和实际召回策略。当前公开文档不承诺某一数据量对应固定毫秒数；对具体场景记录数据规模、冷/热启动和检索耗时。

大文件按实际解析能力导入。work / AckemCode 的文件工具与主应用长期记忆导入是两种用途，不需要把所有任务资源都先导入记忆。

## 兼容与恢复

当前基础 schema 迁移至 V22，另有兼容补表与模块初始化。派生缓存不兼容时可按实现重建；数据库与用户产物不能按缓存删除。旧版程序读取新版数据库不保证兼容，应先在备份副本验证。
